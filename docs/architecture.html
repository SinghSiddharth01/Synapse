Synapse

Every engineer's coding agent learns something. None of them tell each other. Synapse is the listener in between.

Status  approved design, pre-implementation Spec  2026-07-25, amended 2026-08-03 ×6 Measured  NPU/GenieX benchmarks, 2026-07-30 on the X Elite Event  Snapdragon Multiverse, build week Aug 3–7
The idea

When three people chase the same bug, their three agents each rediscover the same things in isolation. Synapse pools what they learn — without anyone writing a note and without changing how they work.

It works by reading a file the agent already writes. Claude Code appends every turn to ~/.claude/projects/<slug>/<uuid>.jsonl; Synapse tails it. A small model on the developer's own NPU turns each chunk of that transcript into a handful of structured findings — a learning, a decision, a dead end, an open question. Those findings, and nothing else, leave the machine. A larger model in the cloud merges everyone's findings into one shared memory, and teammates' agents pull from it over MCP when they ask.

The invariant everything else serves

Raw work never leaves the device. The Finding is the trust boundary — above it, only abstracted text crosses the wire; below it, any model is fair game. Structurally: the worker holds transcripts and no network, the orchestrator holds the network and no raw work, and findings are the only thing that passes between them.

The flow, end to end

One transcript in, ranked findings back out

Everything on the developer's machine sits left of the dashed wall. The edge worker is the only thing that ever sees a raw transcript; the orchestrator is the only thing that talks to the network. Findings enter Synapse through one door and leave through one door, which is what makes the promise auditable rather than aspirational.

Major components

The stages, and the things that cut across them

Numbered in the order a transcript travels. Each stage is defined by what it takes in and what it hands on — which is why the contracts get frozen before any of them get written.

On device — nothing here talks to the network except stage 5
01

File follower

Tails the agent's session JSONL as it grows. Handles rotation, partial trailing lines, and malformed JSON without crashing — the transcript is being written live by someone else's process.

in file on disk  →  out raw JSONL lines
Akhil
02

Source adapter + agent detection

The worker is never configured for an agent — it detects one. A registry maps each known agent to its transcript roots and adapter; fresh activity under a registered root spawns the matching follower and Source, which normalizes that agent's format into the internal event shape. ClaudeCodeSource and CodexSource are the demo pair; any other agent is one adapter plus one registry entry, and nothing downstream ever knows the difference. Compaction summaries an agent writes are ingested as events too — they are high-density signal.

in transcript lines  →  out AgentEvent
Akhil
03

Segmenter + compaction

Batches events into bounded chunks, splitting on turn boundary and on a token budget, so one monster turn becomes several sub-segments rather than one unprocessable blob. The budget is not a constant: it is derived from the resolved distiller's measured capability record — usable context, prefill speed, prompt reserves — so swapping models re-budgets automatically. Compaction is deterministic code, not a model: truncate tool results head and tail, trim thinking, drop trivial calls, strip binary.

in AgentEvent  →  out Segment ≤ budget(model)
Akhil
04

Distiller

The one piece of judgment on the device. A ~4B instruct model turns a segment into structured findings, abstracting rather than quoting — the redaction is a property of the prompt, measured by a deterministic verbatim-copy metric rather than assumed. Measured throughput at 4B on the NPU is ~14 tok/s — fine for a background worker, and stated as a design budget up front rather than discovered during integration.

It also carries a guard learned on real hardware: a mistyped model can silently drop its prompt and stream confident, fluent, invented findings into shared memory. Every distiller call asserts the prompt was actually consumed (usage.prompt_tokens), and a canary fixture fails a model outright before it is ever scored — knowledge poisoning is the one failure the pipeline must never pass through quietly.

in Segment  →  out Finding[]
Aditya
05

Producer client

Posts findings to the local orchestrator. Findings are written to a durable log the moment the distiller returns, before any send is attempted — distillation is the most expensive step in the system and is unrepeatable, since the worker never re-reads a transcript position. A dropped finding is NPU work permanently lost.

in Finding[]  →  out durable log, then localhost POST
Akhil
Orchestrator — local hub, one per machine, the sole egress
06

Orchestrator

The single place findings enter Synapse from this machine, whoever produced them — the worker passively, or the agent deliberately via contribute. It accepts Finding[] and nothing else, stamps Attribution from the LocalBinding it owns, and forwards over HTTPS.

It also hosts the MCP server the agent connects to, which is what makes the awareness layer possible at all: at connect time it already knows the agent product, the Agent Session and the binding, so the arrival briefing can ride the protocol itself. Its own durable log is retained after sending, which turns a service restart from total loss into a resync.

in Finding[] from any producer  →  out HTTPS to the service
split by interface
Service — runs on any laptop, reaches the accelerator over HTTPS
07

Ingest API

Receives findings from every member's worker and handles session create and join. Frozen as a contract on day zero so the sync client can be built and tested against a mock server before the service exists.

in HTTPS POST  →  out Finding[] into the session
Siddsing
08

Synthesis

The reduce half of the map-reduce, on Llama-3.1-8B on hosted Cloud AI 100. Rewrites the bounded working memory, flags contradictions as conflicts, and filters out trivia the small model over-produced.

Its subtlest job is merging. Two findings that mean the same thing produce a new finding capturing the essence of both and carrying both attributions — never discard-one, because "the window is 40 ms" plus "it fails above ~40 ms under load" must not quietly lose "under load". Pooling those halves is the entire product. The originals become tombstones: text kept, excluded from retrieval, never deleted — a retry must still recognise their ids, conflicts must follow them forward, and this merge is an 8B model performing the only irreversible action in the system.

in Finding[]  →  out Working Memory + Conflict[] + curated Finding Log
Siddsing
09

Retrieval

The large model reads the query against the curated Finding Log and ranks — not a vector index. It must rank over the Log, not the working-memory prose: if it ranked raw pushed findings instead, synthesis's dedup and trivia filter would protect nothing a teammate ever sees. Tombstoned and trivial findings never surface.

Nothing reaches an agent whose machine has not joined a session — and once it has, keeping it aware is a design problem in its own right (see retrieval & awareness).

in natural-language query  →  out ranked Finding[]
Siddsing

What moves between them

The contracts

Seven shapes carry the whole system. Freezing them on day zero is what lets three people build in parallel without a daily integration meeting.

ContractWhat it is
AgentEventOne normalized turn part — role, kind (text / thinking / tool_use / tool_result), content, timestamp, cwd, branch. Agent-agnostic and internal to the worker.
SegmentA bounded run of events, split on turn boundary and a per-model token budget (derived from the distiller's measured capabilities, never hard-coded), deterministically compacted. The distiller's unit of work.
AttributionWhere a Finding came from, at three levels — Contributor (the human), Agent Session (the conversation), Agent (the product). One value, so the levels cannot drift apart. Attribution is read at a different level for each job: the human for credit and conflicts, the session for awareness suppression, the product for the cross-agent story.
FindingThe atom of shared knowledge: an id stamped at distil time, a type, abstracted text, a list of attributions, and provenance. This is what crosses the device boundary. The id makes a retried push idempotent and lets conflicts and merge lineage reference findings rather than embed copies.
SynapseSessionThe shared session: id, stated purpose, members. Opt-in by construction — you create one or you join one.
LocalBindingMaps one Agent Session to one Shared Session, carrying the Contributor — effectively the Attribution template for that conversation. Owned by the orchestrator, held in a local file so it survives a restart. One laptop holds several.
ConflictTwo findings that disagree, plus a description. References finding ids, not embedded copies, so a conflict can be updated or resolved rather than frozen at the moment it was found. Surfaced, never silently reconciled.
SessionContextWorking Memory — bounded prose, rewritten each merge to keep synthesis fixed-cost — plus conflicts and a memory_version. Only half of shared memory: the Finding Log is the other half, and it is the half retrieval ranks over.
ModelProvidercomplete(messages, schema?) → ModelResult carrying data, token usage, latency, and whether the output validated. Usage and latency being in the contract is what makes the benchmark nearly free.
The model layer

A mode is a pair

Nothing in the pipeline knows which model it is talking to. A run picks one distiller and one synthesizer, resolved from config at startup — so off-target development on a Mac, on-target demo, and CI all execute the identical code path.

ProviderWhereWrapsRole
FakeProvidertestscripted deterministic outputEvery unit and contract test. No keys, no GPU, no network — quality is measured by the eval harness, never gated in CI.
NPUProvideron-targetgeniex serve at localhost:18181Distillation on the Hexagon NPU — server verified live on the X Elite (OpenAI-shaped, ready ~1 s after launch). Candidates: Qwen3-4B-Instruct, Gemma-4-E4B (after its vlm-mistype fix), Qwen3-1.7B — picked by a bake-off that now includes a GPU arm.

ClaudeProvideroff-targetAnthropic SDKThe quality and cost baseline the small models are measured against — and, at design time, the author of the distiller's few-shot examples.

Ollama, Cirrascale, and GenieX all speak OpenAI-compatible HTTP and differ only by base URL, so four of the five providers share one adapter. Structured output is capability-flagged rather than assumed: neither the NPU nor Cirrascale honors a JSON schema, so those calls use prompt-instructed JSON with a tolerant parse and one retry, and the conformance test measures the schema-valid rate per provider. One asymmetry worth watching: GenieX's CLI exposes GBNF grammar flags, so if the probe finds them plumbed through the server, the edge path gets sampler-guaranteed JSON — better structured-output guarantees than the cloud synthesizer, whose endpoint ignores schemas outright.

Why it's worth doing

Many people, one memory

Everything above describes one machine. The point is what happens when three of them are pointed at the same session: each teammate holds a different slice of the same problem, and today those slices never meet.

Retrieval & awareness

Making the agent remember to remember

Retrieval being agent-initiated creates its own failure: the agent only pulls if it knows memory exists, knows it is relevant right now, and knows whether anything has changed since it last looked. A tool sitting in a tool list conveys none of that. The result is a user typing "check the shared learnings first" at the top of every task — which is exactly the manual labour the product claims to remove.

So awareness gets designed rather than assumed. The mechanism that makes it honest is that joining a session is the consent event. Before an agent joins, Synapse is inert: the tools are listed, nothing is injected, footprint zero. Joining arms everything below it, for that session only. The promise is not "we never push" — it is "we push nothing until you opt in, and only ever pointers, never payload."

And like the capture side, none of it is allowed to be agent-shaped. The four signals below are mechanism-neutral; what is per-agent is only the delivery vehicle, packaged as a thin integration pack that mirrors the Source adapters. The Claude Code pack — hooks plus a skill — is the demo instance described here; a Codex pack delivers the same signals through its own surfaces; and the MCP-native floor (signal ① and the join briefing) needs no pack at all.

The rule that replaces "pull-only"

Membership is the license. Not joined, nothing happens; joined, your agent is kept aware — with headlines, while the bodies still come from a query() the agent chose to make.

Four signals, cheapest first

①

Ambient — the tool description is the nudge

The one signal that is always present and costs nothing: how the tools describe themselves. Written in trigger voice rather than API voice — not "queries the shared memory" but "call before exploring an unfamiliar subsystem, when debugging something a teammate may also be on, or before concluding something is a dead end." The MCP server's instructions field carries the same framing at the server level, which is what a client uses to decide the server is worth reaching for at all.

This tier is pure MCP, so it works in any client with no install — the floor that keeps the agent-agnostic claim intact.

build week
②

Arrival briefing — carried by the protocol itself

Because the orchestrator is local, at MCP initialize it already knows the agent product, the Agent Session and therefore the binding — so the agent never has to be told which session it is in, and there is no attach tool to call. The spec returns an instructions string in the initialize response, generated per connection, and Claude Code uses it. The briefing rides there: purpose, members, counts by type, topic labels, open conflicts, current memory version.

That moves the whole signal out of the per-agent tier and into the floor — any MCP client is briefed on connect, with no install and no hook. Someone joining at hour three learns in one round trip that forty findings predate them and what they are about, without reading any of them. The one thing instructions cannot do is refresh: it is sent once per connection, which is exactly why signal ③ exists.

any client
③

Freshness pointer — speak only on change

A UserPromptSubmit hook checks a cheap watermark endpoint every turn and injects a single line only when the version has moved since this agent last looked, naming the topics that changed. Every other turn it is silent. That silence is the feature: a nudge that fires constantly is one the agent learns to skip past.

The constraint shapes the implementation. This hook runs on the critical path of every prompt with a thirty-second budget, so it can never make a model call — it is one small HTTP request against a precomputed watermark, capped around two seconds, and it fails open.

agent pack
④

Relevance trigger — ship it as a skill

Session start is the wrong moment for most retrieval; the right moment is when the agent is about to do something the team may already have done. That is precisely the problem skills solve — a description the model reads and matches against what it is currently doing. So Synapse ships one, and it auto-loads on relevant work the same way a brainstorming or debugging skill does:

name: synapse-shared-memory description: Use when starting work in a joined Synapse session — before exploring an unfamiliar subsystem, when debugging an issue a teammate may also be on, when an error looks like it could already be known, or before concluding something is a dead end. Checks what the team already learned.

The skill body is short: check the watermark, call query with what you are about to work on, and say plainly when memory had nothing. That last instruction matters — an agent that silently finds nothing is indistinguishable from one that never looked.

agent pack

The mechanics underneath

PieceWhat it does
memory_versionA counter on the shared session, bumped once per synthesis merge. The single source of "has anything changed", and cheap enough to serve on every turn.
last_seen_versionPer member, advanced whenever that agent calls query. The difference against memory_version is the entire staleness calculation.
GET /watermarkReturns {version, new_since, topics, conflicts} and nothing else — precomputed, no model call, safe to hit every turn.
briefing budgetHard-capped near 200 tokens. Headlines and topic labels get pushed; finding bodies never do. The reason is context economy rather than principle — bodies grow with session length, headlines do not.
contributor filterAn agent is never shown findings distilled from its own work. It already knows them, and echoing them back is the fastest way to teach it that memory is noise.

Two rules that keep it from becoming a liability. Every hook fails open — if Synapse is unreachable, slow, or returning nonsense, the hook exits quietly and the agent works exactly as it would without Synapse installed. A memory service that can break someone's coding session is worse than no memory service. And the pointer is rate-limited independently of the watermark, so a burst of teammate activity produces one notice rather than one per turn.

Where it stands

Settled, and still open

Settled

  • Passive capture is real — confirmed against a 5,579-line session with 1,212 tool calls. That corpus is also the fixture and eval set.
  • Cloud AI 100 is a hosted endpoint, verified end-to-end on Aug 3. No box to provision; the spike is retired.
  • The NPU path is geniex serve, verified live on the X Elite — OpenAI-shaped responses a second after launch, so NPUProvider stays a thin subclass.
  • Measured on real silicon: the NPU is the slowest compute unit for LLM decode (memory-bandwidth-bound) — yet wins 14.8× on batched convolution on the same chip. The NPU case for the distiller is contention and power, never speed: it runs always-on work off the critical path while CPU and GPU stay free for the developer. Workload shape, not silicon.
  • Frontier models are design-time only: they author few-shots and diagnose eval failures. Nothing frontier sits in the runtime path.
  • The demo is pre-recorded A/B: the same task without Synapse and with it, side-by-side, with measured deltas — tokens, wall-clock, duplicated exploration. A live run is the encore, which is also what collapses the venue-WiFi risk.
  • Capture is agent-detected, not agent-configured: a registry of transcript roots spawns the right adapter, and Claude Code + Codex are the demo pair. Codex takes MCP servers over localhost HTTP, so the orchestrator is reachable from both.
  • The A/B measures agents, not humans — the same task replayed from fixed repo state, once cold and once with shared memory populated from a real capture. No human learning effect, and runnable N times for variance instead of one anecdote.
  • Findings are durable the instant they are produced and retained after sending, so an orchestrator restart loses nothing and a service restart is a resync rather than a total loss.

Still open

  • Whether the NPU-exclusive qairt path beats llama_cpp — unknowable while AI Hub returns 503. The validated path meanwhile is llama_cpp GGUF with models cached from Docker Hub, and this is the biggest open variable in the edge story.
  • Distiller model choice, decided by a bake-off that now spans NPU, CPU and GPU arms — at 1.7B the Adreno is 2.9× the NPU. Power is still the one unmeasured number, and it is the number the efficiency argument rests on.
  • Synthesis quality on a single 8B model — 70B is not on our key. The honest Claude-vs-8B delta is the demo narrative rather than a thing to hide.
  • Expect the 4B to land around 0.5–0.7 against Claude goldens. Recorded up front so results get read against expectations, not hopes.
  • Distiller and synthesis prompts are first-pass Claude drafts, explicitly not contracts — the eval loop exists to fine-tune them, and mid-week changes are expected.
  • How shared memory is stored for semantic retrieval. In-memory + LLM-as-retriever is the first pass, behind a storage interface; vector RAG, a findings graph, and a purpose→topic hierarchy are the candidate backends once evidence demands one.
  • Who builds the orchestrator. The work is split at its three interfaces so it never blocks on one person, but the component itself was in nobody's plan until the architecture moved — and it is the most expensive item in a five-day build.

Both were replaced on Aug 3 by GenieX and hosted Cirrascale. Optional modules, fallbacks, and the optimistic case

The design above is what ships. What follows is the shape of the system if more of it lands — plus the ladders it degrades down when something doesn't. Both are written in advance for the same reason: a fallback decided under demo pressure is a worse fallback.

Optional module · frontier models

Where a frontier model may attach

"Use Claude for the smart part" is four different proposals wearing one coat, and they have different answers. Sorting them out produced the rule the whole product rests on: the Finding is the trust boundary. Raw work never crosses it. Below it, any model is legal — including the best one available.

①

Frontier as teacher, offline

Claude runs over the fixture segments and its best outputs are frozen into the distiller's prompt as few-shots — including one that deliberately abstracts rather than quotes, which attacks the 4B's two worst expected failure modes. After a benchmark run, the low-scoring cases go back to Claude for failure diagnosis and a proposed prompt revision. About fifty lines on top of the existing harness. Frontier as prompt engineer; never a runtime dependency.

There is a passive version of this too: the agent's own end-of-turn summary is already frontier-written distillation, so compaction weights segments toward assistant text. The 4B summarizes Claude's summaries plus the error lines, not thirty thousand tokens of raw log.

in build week
②

Frontier synthesis below the boundary

Because synthesis and retrieval only ever see findings — already abstracted, already redacted — pointing them at a frontier model is legal by construction and costs one config line. Cloud AI 100 stays the demo path because the hardware thesis is the point, but a team that wants maximum merge quality flips synthesizer: claude and loses nothing but the Qualcomm story. This is also the honest framing of the benchmark: the Claude-versus-8B delta is a number we publish, not one we hide.

config line
③

Escalating hard segments upstream

The tempting one: let the local distiller punt segments it finds hard to a frontier API. Rejected — it ships raw work off-device and deletes the privacy invariant that is the product. Teams that don't need the invariant already have a supported tier for this: set distiller: claude and the whole pipeline runs on frontier models. What is not on offer is doing it silently, per-segment, while still claiming the guarantee.

rejected
④

Contribute — the agent hands over an insight on purpose

MCP is already connected for retrieval, so the agent can push as well as pull. A contribute(text) tool lets the agent write a few sentences of free-form natural language about something it just figured out; the handler wraps that as a synthetic segment and runs it through the same local distiller, tagged provenance: contributed. Frontier does the hard thinking, the local gate does the structuring — and the invariant gets stronger, not weaker: the local distiller becomes the sole entrance to shared memory regardless of how capable the source was.

The toggle is tool availability, not a router in code. The tool description carries the judgment — call this when you've learned something non-obvious a teammate would benefit from — so the agent's own tool-selection is the complexity detector. Compliance is probabilistic, which is fine: the passive path is always running underneath. One contract cost was paid up front to keep this cheap later — provenance is in the Finding schema from day zero.

Backup strategies

What we switch to when something is red

Every risky piece has a written ladder, a trigger, and a drop-dead time. The abstraction layer is what makes most of these cost zero code — which is the actual argument for having built it.

Distiller runtime

GenieX llama_cpp · NPU (validated)→ GenieX llama_cpp · GPU / CPU→ Ollama on the Mac

Trigger: already exercised once for real — the planned first rung, qairt bundles from AI Hub, is blocked by a server-side 503, so the validated llama_cpp path became primary and qairt is now the upside rung if AI Hub recovers (it could reverse the compute-unit ranking). The middle rung is one -c flag on the same server. If it falls all the way to Ollama, the NPU gets presented with whatever partial numbers exist, and the build does not block on it.

Distiller quality

Qwen3-4B-Instruct→ few-shots + prompt-optimizer loop→ Gemma-4-E4B / Qwen3-1.7B→ Qwen3-8B bundle

Trigger: the eval table, not taste. Drop to 1.7B if 4B causes thermal or memory pressure while the developer is working; climb to 8B only if the table says 4B genuinely disappoints. There is also an amber path: if output is close but not schema-valid, keep the NPU, accept the lower rate, and narrate the tolerant parse as the design working.

Synthesizer

Cloud AI 100 · Llama-3.1-8B→ Claude→ Ollama, fully offline

Trigger: venue WiFi, credit pool exhaustion, or rate limits. One environment variable each way, zero code. The edge path never depends on the network at all, so long as the model bundle is cached before the day.

Structured output

native json_schema→ prompt-instructed JSON + tolerant parse→ one retry→ drop the finding

Trigger: already live. Neither the NPU nor Cirrascale honors a schema today, so the middle rung is the normal path, and schema calls to Cloud AI 100 route through /completions because the chat endpoint's tool-call parser eats JSON objects before we ever see them. Capability-flagged and measured per provider rather than assumed — and GenieX's GBNF grammar flags may yet promote the edge path to the first rung, if the probe finds them exposed over HTTP.

Retrieval

LLM-as-retriever→ bge-large embeddings + reranker

Trigger: retrieval quality visibly poor at demo scale. At tens of findings per session, handing the model the whole set and asking it to rank is enough. The upgrade is unusually cheap because both the embedding model and a reranker sit on the same key we already use — but it stays out of core scope, because it is a scaling story rather than a demo problem.

Best case

If all of it lands

The optimistic end state, written as the demo we would record rather than a feature list. The recording pairs this run against a baseline of the same task without Synapse, so every gain below shows up as a measured delta — tokens, wall-clock, duplicated exploration — rather than a claim. Everything here is composed from items above; nothing new is invented.

A lab engineer hits a failure on real hardware and opens a shared session from their Copilot+ PC, declaring its purpose in a sentence. Two teammates join with one command each. Nobody changes how they work — they keep using their own agent, unmodified, and a worker starts reading the transcript it was already writing.
